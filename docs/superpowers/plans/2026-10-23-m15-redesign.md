# 搭伙小灶 M1.5 改版 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 去掉角色、直接注册；「点菜订单」改成谁都能提、谁都能接的「要求」，主线是「提要求 → 算缺料 → 采购（标注 + 推送）→ 打勾入库 → 做好了扣库存」；重做成 今天 / 菜谱 / 采购 / 食材 / 我的 五个页面，点下去立刻有反应；改名「搭伙小灶」；清空测试数据并预设 12 道菜。

**Architecture:** 沿用 M1 的架构（`core/` 纯规则 + n8n 生成的工作流 + Preact 网页）。core 里去掉角色，把 `orders.*` 换成 `requests.*`。前端的 `act` 支持「先改界面，失败再改回」，并把上一次的数据缓存在本机，打开时先显示。新增两个只在服务器内部能调用的 webhook：`pk-reset`（删表）和 `pk-seed`（写预设菜谱）。

**Tech Stack:** 不变：Node 24、n8n 2.44.6、esbuild、Preact 10.29.8、Vite 8.3.4、Vitest 5.0.3。

**Spec:** `docs/superpowers/specs/2026-10-23-dahuo-xiaozao-redesign.md`（优先），基础文档 `docs/superpowers/specs/2026-10-22-pixel-kitchen-design.md`。上一份计划 `2026-10-22-pixel-kitchen.md` 的 Global Constraints 仍然有效，本计划只写变化的部分。

## Global Constraints

- 名字「搭伙小灶」，副标题「一起开小灶」，页面 `<title>` 也改；仓库名和网址（`pixel-kitchen`）不改。
- 没有角色：除 `public` 动作外，所有动作都是 `any`。`pk_users.role` 列保留，值一律为 `'member'`。
- 注册上限常量 `MAX_MEMBERS = 6`（`core/auth.js`），满了返回 `FORBIDDEN`「人满了，最多 6 个人」。
- 要求的状态：`open`（待接）→ `taken`（已接）→ `done`（做好了）；`open|taken` → `cancelled`（只有提要求的人能取消）；`taken` → `open`（只有接的人能「做不了」）。其他跳转一律 `CONFLICT`。
- 同名判断：名字去掉首尾空格、转小写后比较；菜谱只和未删除的比，食材只和未隐藏的比。
- 删除都是隐藏：菜谱用 `archived`，食材新增 `hidden` 列，采购项用 `removed`。
- 推送事件以规格 §2.3 为准（下面 Task 2 列了事件名和字段）。
- 前端底部导航固定是：今天 / 菜谱 / 采购 / 食材 / 我的。本机缓存的键是 `pk.view.<token 前 8 位>`，退出登录时删除。
- 改动生产数据的脚本必须先备份，并让用户手动输入 `RESET` 确认（用户偏好：脚本里要内置确认和撤销手段）。

## Review Focus

1. **先改了界面，服务器却返回失败** → 界面改回原样，并显示服务器给的中文原因，不能停在一个假状态上。测试：Task 5 `optimistic change reverts on error`。
2. **两个人同时点「接下」同一个要求** → 后点的那个人收到「已经有人接了」，界面刷新后显示的是先接的人。测试：Task 2 `second take conflicts`、Task 6 `take conflict refreshes`。
3. **同一台手机换账号登录** → 不能闪现上一个人的缓存数据。测试：Task 5 `cache is per account and cleared on sign out`。
4. **名字前后带空格、大小写不同**（「鸡蛋 」和「鸡蛋」、「Tofu」和「tofu」）→ 都算重名，提示后直接打开已有的那一项。测试：Task 3 `duplicate names ignore spaces and case`、Task 8 `duplicate opens existing item`。
5. **重置脚本误跑在有真实数据的生产环境** → 先备份，没有输入 `RESET` 就什么都不做。验证：Task 10 Step 2（手动验证脚本拒绝执行）。

  - 删表节点的参数名，用服务器上的镜像确认：`sudo docker run --rm --entrypoint sh n8nio/n8n:2.44.6 -c 'cat /usr/local/lib/node_modules/n8n/node_modules/n8n-nodes-base/dist/node-definitions/nodes/n8n-nodes-base/dataTable/v11/resource_table/operation_delete.ts'`
